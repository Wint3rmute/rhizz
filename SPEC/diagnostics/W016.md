# W016 — View node references unknown component

**Warning level:** Architectural.

A `node` block inside a `view` names a component path that does not resolve to
any component in the project. Node paths use the diagram editor's
structurally-stable keys: a system-scoped label path
(`computer-setup/computer/cpu`) or a top-level definition label (`cpu`).

This is emitted as a warning (non-blocking) because view layout is presentation
metadata: a stale node — left behind by a rename or deletion — must not block
the system model from compiling. The node simply has nothing to render and is
ignored until the path is fixed.

## Example (warning)

```hcl
# views/overview.hcl
view "overview" {
  system = "computer-setup"

  node "computer-setup/not-a-computer" {   # Warning: no such component
    x = 20
    y = 50
  }
}
```

Here the view targets `computer-setup`, but `not-a-computer` is not a component
in the system (or anywhere else in the model).

## Fix

Use the label path of a component that exists. For a nested component, spell
out every ancestor label from the system down:

```hcl
# views/overview.hcl
view "overview" {
  system = "computer-setup"

  node "computer-setup/computer" {
    x = 20
    y = 50
  }
}
```

If the component was renamed or removed, either update the node to its new path
or delete the node block — the diagram editor writes these paths automatically,
so hand-edited views are usually the source of drift.
