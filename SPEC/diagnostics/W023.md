# W023 — View filter requires a component the view does not show

**Warning level:** Architectural.

A `view` with a `filter { include_tags = [...] }` block promises to show every
component of its system that carries at least one of those tags. This warning
names a component that matches the filter but is not placed as a `node` in
the view.

The filter is a **coverage contract**, not a selection: layout stays
hand-placed, and the compiler checks that the diagram has not drifted from the
model. Adding a new `power`-tagged component to the system makes every view
filtering on `power` report it until someone places it.

Only components of the view's own `system` are considered; top-level
definitions and components of other systems never match. A component counts
as shown only when it has its own `node` block — a placed ancestor does not
satisfy the filter. A view without `include_tags` requires nothing.

It is a warning (non-blocking) because views are presentation metadata: an
incomplete diagram must not stop the system model from compiling.

## Example (warning)

```hcl
# system.hcl
component "battery" {
  leaf = true
  tags = ["power"]
}

component "esc" {
  leaf = true
  tags = ["power", "motor"]
}

system "quad" {
  instance "battery" { source = "battery" }
  instance "esc" { source = "esc" }
}
```

```hcl
# views/power.hcl
view "power" {
  system = "quad"

  filter {
    include_tags = ["power"]
  }

  node "quad/battery" {   # OK
    x = 20
    y = 50
  }

  # Warning: `quad/esc` is tagged `power` but has no node.
}
```

## Fix

Place the missing component in the view (in the Modeling editor, tick it in
the component tree):

```hcl
# views/power.hcl
view "power" {
  system = "quad"

  filter {
    include_tags = ["power"]
  }

  node "quad/battery" {
    x = 20
    y = 50
  }

  node "quad/esc" {
    x = 140
    y = 50
  }
}
```

If the component should not appear in this view, either drop the tag from the
component or remove it from the view's `include_tags`.
