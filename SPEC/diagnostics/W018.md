# W018 — Component missing documentation

**Warning level:** Component.

A top-level component definition (`component "<label>" { ... }`) has no
Markdown documentation file under `docs/` (`docs/<label>.md`, matched by
label). Documentation is a first-class citizen: every reusable definition
should explain what it is, not just carry a one-line `full_name`.

Like the missing `full_name` check (W004), this applies to **definitions
only** — an instance clones its definition's body, so the defect is reported
once on the definition, never duplicated per instance.

Doc files are part of the compilation sources: any file under a `docs/`
directory ending in `.md` counts (e.g. `docs/motor.md` documents
`component "motor"`). Only the filename matters, not its content. A nested
path also matches when its final segment equals the label
(`docs/sub/motor.md` documents `motor`), so reorganizing docs into folders
does not silence the warning unexpectedly.

## Example (warning)

```hcl
component "motor" {
  full_name = "Brushless DC motor driving one propeller"
}
```

No `docs/motor.md` exists, so `motor` is flagged.

## Fix

Create the missing doc file:

```markdown
# Motor

Brushless DC motor driving one propeller. Rated for 4S packs, ...
```
