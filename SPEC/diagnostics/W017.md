# W017 — View node outside the view's system

**Warning level:** Architectural.

A `node` block inside a `view` names a component that exists, but belongs to
a different system than the view's bound `system`. Node paths use the diagram
editor's structurally-stable keys: a system-scoped label path
(`computer-setup/computer/cpu`) whose first segment is the owning system.

This is emitted as a warning (non-blocking) because view layout is
presentation metadata: a node from another system must not block the system
model from compiling. The Modeling web editor hides such nodes (they are kept
in the file, never deleted) and shows a "+N hidden from other systems" hint
until the paths are fixed — one view shows one system.

Bare top-level definition labels (e.g. `cpu` with no system prefix) are
exempt: definitions are global and belong to no system. Unknown paths are
reported as `W016`, never `W017`.

## Example (warning)

```hcl
# diagrams/overview.hcl
view "overview" {
  system = "computer-setup"

  node "computer-setup/computer" {   # OK: own system
    x = 20
    y = 50
  }

  node "test-rig/oscilloscope" {     # Warning: lives in "test-rig"
    x = 20
    y = 150
  }
}
```

Here the view targets `computer-setup`, but `oscilloscope` is placed in
`test-rig`.

## Fix

Point the node at a component in the view's own system, or move the node
into a view bound to the system it lives in:

```hcl
# diagrams/overview.hcl
view "overview" {
  system = "computer-setup"

  node "computer-setup/computer" {
    x = 20
    y = 50
  }
}
```

```hcl
# diagrams/test-rig.hcl
view "test-rig" {
  system = "test-rig"

  node "test-rig/oscilloscope" {
    x = 20
    y = 150
  }
}
```

If the component was moved between systems, either update the node to its new
path or delete the node block — the diagram editor writes these paths
automatically, so hand-edited views are usually the source of drift.
